02为什么这样分工

直觉上「换 electron-builder」应该是让 electron-builder 从头打包，但这个项目做不到 —— Forge 的 vite 插件在构建时把 MAIN_WINDOW_VITE_DEV_SERVER_URL、 MAIN_WINDOW_VITE_NAME 这类全局变量注入到主进程产物里， 而项目里的 vite.main.config.mjs 本身是空的（defineConfig({})）， 入口与注入全靠插件。换打包器就得把整套 vite 配置重做一遍。

所以采用「各管一段」的分工：Forge 编译打包，electron-builder 只做安装包， 两者用 --prepackaged 衔接。

03命名约定（最容易踩的坑）

NSIS 模板里安装器是这样算主程序文件名的： 

# electron-builder · templates/nsis/common.nsh
!define APP_EXECUTABLE_FILENAME "${PRODUCT_FILENAME}.exe"

而 PRODUCT_FILENAME 取自 electron-builder 的 productName （appInfo.productFilename，未设置 executableName 时用 sanitizeFileName(productName)）。也就是说，如果 electron-builder.yml 里的 productName 与 Forge 打出来的 exe 名不一致，快捷方式就会指向一个不存在的文件： 安装过程一切正常、没有任何报错，但用户点图标打不开 —— 这类错误在构建阶段完全看不出来。

因此 productName 必须与 forge.config.js 里 packagerConfig.name 保持同一个值（当前是 Miao积分管理）。 两个文件里都写了注释说明这条约束。

本次一致性核对结果
  • out/Miao积分管理-win32-x64/Miao积分管理.exe Forge 实际打出来的主程序
  • sanitizeFileName("Miao积分管理") = "Miao积分管理" 中文不会被过滤，PRODUCT_FILENAME 与上面对齐
  • => APP_EXECUTABLE_FILENAME = Miao积分管理.exe 快捷方式目标正确

唯一保留中文的标识是 exe 名与安装目录（%LOCALAPPDATA%\Programs\Miao积分管理）； 安装包文件名是 ASCII（miao-chemistry-Setup-2.0.1.exe）。 如果以后想把 exe 也改成 ASCII，需要同时改 packagerConfig.name， 注意那会一并影响 macOS 的 .app 名与 DMG 文件名，属于独立的一次改名，建议单独排期。

05旧版本一次性迁移

旧版是 Squirrel 安装的：程序在 %LOCALAPPDATA%\student-score-system， 卸载项写在 HKCU\...\Uninstall\student-score-system。两套安装器互不知情， 所以 build/installer.nsh 里挂了两个钩子做清理。

表 3 · 两个钩子的时机与动作
钩子执行时机做什么为什么在这个时机
customInit 安装最早期，尚未写入任何文件 按通配删除桌面与开始菜单里旧版的「Miao积分管理*.lnk」 此刻我们自己的快捷方式还没创建，不会误删；通配能覆盖带版本后缀的命名
customInstall 文件落盘、快捷方式创建完成之后 删掉旧安装目录与旧卸载注册表项 此时 electron-builder 已把仍在运行的旧版本进程关掉，目录才删得干净

全部清理都是 best-effort：NSIS 的 RMDir / Delete 失败只设置错误标志、 不中断安装。最坏情况是留下一个可手动删除的残留目录，安装本身不受影响。 用户数据不受影响 —— 班级、学生、积分都在 %APPDATA%\miao-chemistry， 与安装目录无关，deleteAppDataOnUninstall 也已显式设为 false。

06验证记录与待验证项

已在本机跑通的（macOS + Node 20）

  • Forge 打包步骤正常，产物为 out/Miao积分管理-win32-x64，主程序名与预期一致
  • 脚本能正确定位产物目录并把中文路径原样传给 electron-builder
  • NSIS 安装包构建成功：dist/miao-chemistry-Setup-2.0.1.exe，91 M，oneClick=false perMachine=false 均已生效
  • 自定义脚本确实被注入在钩子使用点之前 —— 已从生成的脚本中确认 !include ".../build/installer.nsh" 出现在 !ifmacrodef customInit 之前
  • exe 名一致性链条核对通过（见第 03 节）
  • 锁文件同步：yarn install --frozen-lockfile 通过，CI 安装路径可用
  • 改动后的 src/main.js 通过 vite 编译（Forge 打包步骤即验证）

需要在 Windows 上确认的

  • 全新安装：向导界面、快捷方式、是否无需管理员权限
  • 覆盖升级：先启动旧版再运行新安装包，确认能自动关闭旧版并装完（本地无法验证安装器运行时行为）
  • 一次性迁移：确有旧 Squirrel 版本时，确认控制面板只剩一条卸载项、桌面无重复图标、得分数据仍在
  • 卸载：确认程序目录被清理、%APPDATA%\miao-chemistry 保留
  • 杀软：360 / 火绒 / Defender 下能否正常安装（未签名安装包仍可能被拦，见第 07 节）

本地能跑通的是「构建产物是否正确」，跑不了的是「Windows 安装器的运行时行为」。 这些必须在真机或 CI 的 windows 机器上过一遍，建议在发版前用一台干净机器 + 一台装过旧版本的机器各测一次。

07回滚与后续可选项

回滚

git revert <本次提交>        # 或按文件恢复
git checkout HEAD -- forge.config.js package.json src/main.js \
  .github/workflows/build.yml README.md yarn.lock
rm -f electron-builder.yml scripts/build-windows.mjs build/installer.nsh

回滚后 Windows 侧仍会走原来的 Squirrel 流程（脚本命令名未变，只是内部实现换回 forge make）。

后续可选

  • 代码签名（收益最大）：配好 CSC_LINK / CSC_KEY_PASSWORD 即自动生效，SmartScreen 提示与杀软误报会明显减少。
  • 绿色版：放开 electron-builder.yml 里注释掉的 portable 段，多产出免安装 exe，给权限受限的机器兜底。
  • 自动更新：接 electron-updater（NSIS 场景成熟）或用 Velopack；后者支持 GiteaSource，正好复用现有 Gitee 同步脚本。建议单独排期。
  • 标识 ASCII 化：把 packagerConfig.name 与 productName 一起改成 ASCII，可顺带简化安装目录与日志排查，但会影响 macOS 的 .app 名，属于独立改名。
  • 「Build Windows」的 BUILD_TYPE 回退值：workflow 里 github.event.inputs.build_type || 'trial' 会让 tag 推送打成 trial（30 天），与注释里写的「默认 official」不符 —— 本次未动，需要时改成 || 'official' 即可。
