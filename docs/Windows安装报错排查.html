Windows 安装包报错排查：Squirrel 安装链路分析

01结论先行

是谁报的

Squirrel.Windows 的 Setup.exe 自己。Setup.exe 是个自解压外壳：先把内嵌的 updater 解到临时目录，再执行 Update.exe --install .，只有这个子进程退出码不为 0 才弹这句。

最常见的真因

安装新版本时，Squirrel 会把 %LOCALAPPDATA%\student-score-system 整个目录删掉重装。只要其中任何一个文件被占用（旧版进程没退干净、杀软扫到一半、资源管理器/网盘持有句柄），删除就失败，退出码非 0，于是弹窗。

和签名强相关

本项目的 Windows 安装包完全没有做 Authenticode 签名，Update.exe 与主程序都容易被 360 / 火绒 / Defender 拦下或改写，落到日志里就是「找不到文件」「无法拷贝」。electron-winstaller 官方 README 对未签名包的原话就是「many anti-virus vendors will consider your app as malware」。

一个可以先排除的误区

发布时只上传那个 exe 是够的。Setup.exe 内部已嵌入应用负载（构建时由 WriteZipToSetup.exe 写入），旁边的 *-full.nupkg 和 RELEASES 只服务于「自动更新服务端」场景。所以「缺 nupkg 导致安装失败」这条可以先划掉。

02这条报错是谁弹的

报错文案里的关键词是 setup log 和 contact the author，这是 Squirrel.Windows 安装器自带的话术。在本机安装链路上，你双击的那个安装包做的是下面五件事， 任何一步失败都会走到同一句弹窗上。

源头代码

这句话在 Squirrel.Windows 源码里只有一处，判据是子进程退出码：

// src/Setup/UpdateRunner.cpp · CUpdateRunner::ExtractUpdaterAndRun
swprintf_s(cmd, L"\"%s\" --install . %s", updateExePath, lpCommandLine);
CreateProcess(NULL, cmd, NULL, NULL, false, 0, NULL, targetDir, &si, &pi);
WaitForSingleObject(pi.hProcess, INFINITE);
GetExitCodeProcess(pi.hProcess, &dwExitCode);

if (dwExitCode != 0) {
    DisplayErrorMessage(CString(
        L"There was an error while installing the application. "
        L"Check the setup log for more information and contact the author."), logFile);
}

注意 targetDir 同时是子进程的工作目录，也就是 --install . 里的那个「.」—— updater 解出来的 RELEASES、packages\*.nupkg 都来自这里，所以安装包本身是自包含的。

04现场取证：日志在哪

不要再靠猜。这条弹窗上有一个 Open Setup Log 按钮，点它打开的就是唯一权威现场。 也可以直接去下面两个路径找，第一个是主路径，第二个是 %TEMP% 不可写时的回退路径。

SquirrelSetup.log
  • %LOCALAPPDATA%\SquirrelTemp\SquirrelSetup.log 主路径：C:\Users\<用户名>\AppData\Local\SquirrelTemp\SquirrelSetup.log
  • C:\ProgramData\<用户名>\SquirrelTemp\SquirrelSetup.log 回退路径：主路径无法写入时使用

拿到日志后按第 03 节的关键字对号入座即可。Setup.exe 自己只把「退出码非 0」翻译成一句通用话术， 不会透露是哪一步挂的——信息全在日志里。

05为什么「每次新版本」必现

「每次新版本都报」这个说法有两种读法，判据不同，指向的原因也不同。先分清楚是哪一种，再决定查哪个方向。

表 2 · 两种情形的判据与方向
情形现象特征更可能的真因
首次安装（干净机器）就失败 这台机器上从没装过本应用，%LOCALAPPDATA%\student-score-system 不存在 环境性问题：杀软拦截未签名安装器、缺少 .NET Framework 4.5.2+、%LOCALAPPDATA% 被策略重定向或不可写、安装包下载不完整（校验 hash）
覆盖升级失败（老版本已装） 首次能装，装新版本时才报；或者是同一版本重复安装 旧目录删不掉的占用问题（本项目最高概率）、旧版进程/残留实例、版本号未严格递增导致的残留状态

之所以本项目在「覆盖升级」这一侧风险偏高，有三个叠加因素：

  • 没有单实例锁。全库检索 requestSingleInstanceLock 零命中，用户可以同时开多个窗口，升级时被占用的概率被放大。
  • 每一次升级都是「整目录删掉重装」。这是 Squirrel 的设计，不是 bug；任何句柄占用都会直接失败，容错远低于覆盖式安装。
  • 没有签名。未签名程序被安全软件扫描、隔离、改写的概率显著更高，正好都发生在「删目录 / 拷文件」这两步。

06规避清单

按「先定位、再止血、最后根治」的顺序，性价比从高到低。

  1. 先取一次日志，别猜让出问题的用户点弹窗上的 Open Setup Log，回传 SquirrelSetup.log。日志里那一行决定了后面该做什么；没有日志就去改配置属于盲改。
  2. 规范装机动作安装前彻底退出旧版（含托盘/后台），任务管理器确认没有 Miao积分管理.exe 残留；随后直接双击安装包，不要右键「以管理员身份运行」——Squirrel 明确拒绝提权运行，会走另一条报错分支。文件仍在占用时，重启一次再装是最省事的兜底。
  3. 给安装链路加白名单在教师机器的安全软件里放行安装目录 %LOCALAPPDATA%\student-score-system、临时目录 %LOCALAPPDATA%\SquirrelTemp，并说明这是本应用安装器。这一步不需要改代码，但能消掉相当比例的现场。
  4. 补上单实例锁加 app.requestSingleInstanceLock()，减少多实例并存；同时确保退出时释放数据文件句柄。这既降低升级失败率，也避免数据互相覆盖。
  5. 版本号每次严格递增tag（如 v2.0.2）必须同步成 package.json 的新版本号，不要复用旧号重发。发布前在一台干净 Windows 上做一次「覆盖安装 + 卸载重装」回归。
  6. 给安装包和主程序做代码签名这是这类问题最根本的一刀：SmartScreen 提示、杀软误报、被拦截改写，基本都源于未签名。OV/EV 代码签名证书都能用；成本换来的是一整类问题消失。
  7. 评估换装安装器（根治）Squirrel.Windows 已停止维护，官方推荐的迁移目标是 Velopack；或改用 electron-builder 的 NSIS。两者都是覆盖式安装，不再「整目录删掉重装」，对句柄占用和杀软干扰的容错明显更高。

方案升级方式优势代价
