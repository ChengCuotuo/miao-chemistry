01

需求与落地映射

REQ 1树形结构，最多两层
新增 规则分组 概念，形成「分组 → 规则」两层树。分组不可再嵌套，规则是叶子节点，结构被硬性限定为两层。设置页用可展开的树形表格呈现，选择器用 el-tree-select 呈现。
REQ 2兼容老数据，归入默认分组
读取时识别两种格式：旧的扁平规则数组与新的 { groups, rules } 对象。旧数据在加载时逐条写入默认分组 id，缺失或指向已删除分组的规则同样回落到默认分组。默认分组内置且不可删除。
REQ 3支持自定义分值规则
规则分值改为 number | null，null 即自定义分值规则。设置页新增「自定义分值规则」开关，开启后不再填写固定积分值，列表中显示为自定义分值标记。
REQ 4其他选择规则处改树形
抽出共享组件 RuleTreeSelect，把关联分组（单个/批量）、独立分组（小组/成员）、周期记分三处的规则下拉全部替换为按分组展开的树形选择。
REQ 5自定义分值规则须先设分值才生效
选择自定义分值规则时，弹窗自动出现「本次分值」输入项，未填写则校验拦截、确定按钮不生效；周期记分入口在数据层再次校验，缺分值直接返回失败提示，保证不会写入 0 分记录。
02

数据模型

新增 RuleGroup 实体，Rule 增加 group_id 与 order 字段，分值放开为可空。两者随 rule.json 以 { groups, rules } 结构统一持久化。

03

老数据兼容与迁移

迁移在读取阶段完成，不修改旧文件、不要求用户操作。加载时判断顶层结构：数组视为旧格式，对象视为新格式。

  • 旧格式（数组）：等价于「全部规则都在默认分组」，逐条补上 group_id = DEFAULT 与顺序号。
  • 新格式（对象）：读取 groups / rules；若对象里缺失默认分组则补建。
  • 兜底规则：任何 group_id 为空、或指向已被删除分组的规则，一律回落到默认分组，避免规则「消失」。
  • 写回时机：首次发生增删改或导出时，文件自然改写为新格式，之后不再走迁移分支。
  • 导入兼容：导入同时接受旧版扁平数组文件与新版含分组文件，旧文件按默认分组导入。
04

规则设置页：树形管理

设置页由「扁平分页表格」重构为「两层树形表格」：分组为父行、规则为子行，默认全部展开。父行提供新增规则、重命名、删除；子行提供编辑、删除。顶部新增「新增分组」入口。

  • 分组行：显示分组名 + 规则条数，可直接在该分组下新增规则。
  • 规则行：显示分值标签（+n −n 自定义分值）、适用班级、描述。
  • 删除分组：组内规则自动迁移到默认分组后再删除分组，规则不丢失；默认分组禁止删除。
  • 筛选态：命中搜索/类型/班级筛选时切换为扁平列表，并额外显示「所属分组」列，便于跨组查找。
  • 自定义分值开关：规则表单中开启后隐藏积分值输入，保存时写入 null。
系统内置规则：「主动加分」「主动减分」带「系统」标记，界面禁用删除 + 数据层拦截双重防止误删（保障快捷加减分入口始终可用），名称/描述/分值仍可正常编辑。
05

06

自定义分值规则的生效机制

自定义分值规则不在规则库中预设分值，选择时必须现场赋值才生效。这是「选择 → 校验 → 落库」三段式约束，UI 层与数据层双重把关。

要点：周期记分走 adjustPointsByRule，对自定义分值规则若未带单次分值，直接返回失败提示，避免写入 0 分记录；统计与记录页仍按记录中的真实分值展示。
