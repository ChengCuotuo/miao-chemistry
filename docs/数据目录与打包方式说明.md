# 换成 NSIS 打包后，应用读取的数据还在原来的位置吗

> 结论：**没变**。数据仍在 `%APPDATA%\miao-chemistry`，与之前的 Squirrel 版是同一个目录，用户不需要做任何数据迁移。
>
> 对应分支：`develop-builder-win`（v2.0.2）

## 一、为什么不会变

这个路径不是安装器决定的，而是由「应用自身标识」决定的。Electron 按下面的顺序算出目录，安装器（Squirrel 或 NSIS）只负责把程序放上去，不参与这件事：

1. 应用包内 `package.json` 的 `productName` = `"miao-chemistry"`（NSIS 分支与旧分支完全一致）
2. Electron 的 `app.name` 优先取 `productName`——**不是 exe 名（`Miao积分管理.exe`），也不是安装目录名**
3. `app.getPath('userData')` = `%APPDATA%` + `app.name`
4. 得到 `%APPDATA%\miao-chemistry`

代码里所有读写都走这个路径：

```js
// src/main.js
const userDataPath = app.getPath('userData');
// 后续所有 read-file / write-file / load-file-path 都在 userDataPath 之下
```

渲染进程没有使用 `localStorage` / `IndexedDB`，全部数据都是主进程写在 `userData` 下的文件，因此不存在「另一处存储」被落下的可能。

### 最容易误判的一点

`electron-builder.yml` 里也有一个 `productName: Miao积分管理`，但它只作用于**安装器层面**——安装向导标题、快捷方式名称、控制面板卸载项显示名。它不会写进应用内的 `package.json`，因此不影响 `app.name`，也不影响数据目录。

真正决定数据目录的是 `package.json` 里的 `productName: "miao-chemistry"`。这也是改造时特意把 exe 名（`packagerConfig.name`）与安装器的 `productName` 对齐、却**没有去动** `package.json` 里标识的原因：一旦改标识，数据目录会跟着变，用户就会以为积分数据全丢了。

## 二、实证

| 验证项 | 方法 | 结果 |
| --- | --- | --- |
| 安装包不改动应用 | Forge 打出 Windows 包后记录 `app.asar` 的 SHA-256，再跑一次 electron-builder 生成 NSIS 安装包，重新计算哈希 | **前后完全一致**（`ce636b80…cfa`），同一时间正常产出了 91 MB 安装包；安装器往程序目录里只多放了一个 `resources/elevate.exe`（权限提升辅助程序），与数据无关 |
| 应用标识未变 | 对比 NSIS 分支与旧分支的 `package.json` | `name` 与 `productName` 都是 `miao-chemistry` |
| 实际落盘位置 | 查看本机应用真实写入的数据目录 | 数据确实落在以 `miao-chemistry` 命名的目录下（`group-points/rule.json`、`grade.json` 等），而不是中文名目录 |

第一条接近决定性证据：`--prepackaged` 让安装器只接管 Forge 已打好的目录、不重新打包，所以它没有机会改写应用内容。第三条在本机（macOS）验证的是同一套命名机制，Windows 上对应 `%APPDATA%\miao-chemistry`。

## 三、换装之后，哪些路径变了

| 内容 | 旧版（Squirrel） | 新版（NSIS） |
| --- | --- | --- |
| 程序目录 | `%LOCALAPPDATA%\student-score-system\app-<版本>` | `%LOCALAPPDATA%\Programs\` 下按产品名生成的新目录 |
| 快捷方式 | 桌面 + 开始菜单 | 同上，由新安装器重建 |
| 卸载项 | `HKCU\...\Uninstall\student-score-system` | 新的卸载项；安装脚本会顺手清掉旧的那条 |
| 更新机制 | Squirrel（整目录替换） | NSIS（覆盖写入） |
| **用户数据** | `%APPDATA%\miao-chemistry` | `%APPDATA%\miao-chemistry`（**不变**） |

数据的目录结构不变，仍是 `userData` 下的 `group-points\*.json` 等文件：

```
%APPDATA%\miao-chemistry\            (C:\Users\<用户名>\AppData\Roaming\miao-chemistry\)
└─ group-points\
   ├─ rule.json
   ├─ grade.json
   └─ prize.json  等积分数据
```

## 四、两个需要注意的点

### 1. 新旧两版共用同一份数据

正因为路径不变，如果机器上旧版没卸载、两版又都被启动过，它们会读写同一批文件。旧版代码不认识新版本新增的字段（例如班委相关数据），在用旧版保存时可能把这些字段覆盖掉。旧版没有单实例锁，两版可以同时开着，这个风险是真实存在的。

所以「升级时先卸载旧版」这条不只是为了控制面板整洁，也是数据安全的考虑。

好消息是：卸载旧版不会删除 `%APPDATA%\miao-chemistry`，新安装包也已显式设置卸载时保留用户数据（`deleteAppDataOnUninstall: false`），升级后打开应用即可看到原有数据，不需要导入导出。

### 2. 什么情况下数据路径会变

- **改 `package.json` 的 `productName` 或 `name`**（例如标识 ASCII 化，或改成中文名）：数据目录整体换路径，在用户看来就是「积分全没了」。真要做这种改名，必须同时写一个把旧目录搬到新目录的迁移逻辑。
- **代码里显式 `app.setPath('userData', …)`**：目前没有这么做，也不建议在换安装器时顺手加。
- **换了 Windows 登录账号或换了电脑**：`%APPDATA%` 是每个用户独立的，与打包方式无关，但会让人误以为是升级导致的数据丢失。
- **绿色版（portable）也没影响**：仍会把数据放在 `%APPDATA%`，除非应用自己去读 `PORTABLE_EXECUTABLE_DIR`。

### 怎么自查

装好新版后按 `Win + R`，输入 `%APPDATA%\miao-chemistry` 回车，能看到 `group-points` 目录里的 json 文件，就说明读的是同一份数据。也可以在应用里改一条积分，再回来看文件时间戳是否更新。

## 五、顺带一处提示（与数据路径无关）

NSIS 分支的 `electron-builder.yml` 里 `directories.output` 目前是 `dist`，而 `dist` 恰好是渲染器 `vite build` 的默认输出目录（默认会清空）。本地跑一次渲染器构建就会把安装包删掉，建议改成 `release` 之类的独立目录，并把 CI 的上传路径一并改过去。
